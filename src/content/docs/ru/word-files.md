# Файлы Word и большие документы

На этой странице описаны открытие и сохранение файлов Word, открытие и скачивание PDF, а также инструменты для больших документов: сноски, многоуровневая нумерация, параметры нумерации страниц, страницы разной ориентации, оглавление и область навигации.

## Файлы Word (.docx)

### Сохранение в формате Word

Пункт «Скачать как Word (.docx)» в меню «Ещё» или `exportWord()` у ref шаблона скачивает настоящий файл Word в формате Office Open XML. Его можно открыть для редактирования в Word, LibreOffice, Google Docs и других офисных пакетах. Имя файла берётся из пропса `title`.

В файле сохраняются:

- абзацы и заголовки с выравниванием, отступами, интервалами между абзацами, межстрочным интервалом и направлением текста;
- полужирный, курсив, подчёркивание, зачёркивание, подстрочный и надстрочный индексы, цвет текста, выделение цветом, шрифт и размер шрифта;
- ссылки, цитаты и блоки кода;
- маркированные и нумерованные списки с вложенностью, начальным номером и многоуровневой нумерацией; пункты чек-листов получают символы ☐ и ☑;
- таблицы с объединёнными ячейками и шириной столбцов; блоки подписи и оглавление — без границ;
- изображения в форматах PNG, JPEG, GIF и BMP;
- сноски — как собственные сноски Word;
- отслеживаемые изменения — как исправления Word с автором и временем;
- разрывы страниц, разрывы разделов (как разделы Word) и горизонтальные линии;
- размер бумаги, ориентация и поля, колонтитулы с полями PAGE и NUMPAGES, водяной знак и параметры нумерации страниц.

Переменные шаблона записываются как текст `{{name}}`, а комментарии не включаются: прокомментированный текст остаётся.

Изображения по веб-адресу загружаются во время сборки файла, поэтому сервер должен разрешать такой запрос (CORS). Изображение, которое не удалось прочитать, или изображение в другом формате, например WebP или SVG, пропускается.

`buildDocx` собирает такой же файл в вашем коде — например, чтобы загрузить его на сервер вместо скачивания:

```ts
import { buildDocx } from 'nuvra';

const blob = await buildDocx({ html, title: 'Договор', page });
await fetch('/api/documents/42/docx', { method: 'PUT', body: blob });
```

### Открытие файла Word

Пункт «Открыть файл Word (.docx)» в меню «Ещё» предлагает выбрать файл и заменяет документ его содержимым. Размер бумаги, ориентация, поля, тексты колонтитулов и нумерация страниц тоже берутся из файла; текущий водяной знак сохраняется. Файл с несколькими разделами приходит с разрывом раздела в начале каждого следующего раздела; см. [Страницы разной ориентации](#страницы-разной-ориентации). Замена содержимого — один шаг отмены. Пункт недоступен, пока редактор находится в состоянии `disabled`.

Из кода то же самое делает `importWord(file)`. Если файл не удаётся прочитать, документ не меняется и генерируется событие `importError`:

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { DocumentEditor } from 'nuvra';

const html = ref('');
const editor = ref<InstanceType<typeof DocumentEditor>>();

const open = (event: Event) => {
  const file = (event.target as HTMLInputElement).files?.[0];
  if (file) void editor.value?.importWord(file);
};
</script>

<template>
  <input type="file" accept=".docx" @change="open" />
  <DocumentEditor ref="editor" v-model="html" @import-error="error => console.error(error)" />
</template>
```

Импорт читает абзацы и заголовки (стили Heading 1–6 и Title, а также стили с уровнем структуры), форматирование абзацев и символов, ссылки, списки, включая многоуровневую нумерацию, таблицы с объединёнными ячейками, изображения, разрывы страниц, сноски, исправления и элементы управления содержимым. Вставки и удаления Word становятся отслеживаемыми изменениями редактора, поэтому документ, прорецензированный в Word, возвращается с по-прежнему открытыми изменениями. Изображения встраиваются как data URL и не проходят через `uploadImage`. Таблица без границ становится таблицей без границ, как блок подписи.

`readDocx` возвращает результат без редактора:

```ts
import { readDocx } from 'nuvra';

const { html, page } = await readDocx(await file.arrayBuffer());
```

### Ограничения

| Возможность Word | Что происходит |
| --- | --- |
| Сноски | Сохраняются в обоих направлениях; при импорте читается только текст сноски, её форматирование теряется. |
| Концевые сноски | Не импортируются. |
| Исправления | Вставки и удаления текста сохраняются в обоих направлениях. Текст, помеченный в Word как перемещённый, приходит удалением на старом месте и вставкой на новом. Исправление форматирования приходит как новое форматирование без исправления. |
| Примечания Word | Не импортируются. |
| Несколько разделов | Каждый раздел после первого начинается с разрыва раздела с ориентацией этого раздела. Документ получает размер бумаги, ориентацию, поля, параметр титульной страницы и номер первой страницы из первого раздела; другие размеры бумаги и поля последующих разделов не сохраняются, а непрерывный раздел начинается с новой страницы. |
| Особый колонтитул первой страницы | Параметр сохраняется, но содержимое колонтитулов первой страницы не импортируется. |
| Колонтитулы | Импортируется только их текст, разделённый на левую, центральную и правую части; форматирование и изображения теряются. |
| Водяной знак, надписи, фигуры | Не импортируются. |
| Поля | PAGE и NUMPAGES в колонтитулах становятся `{page}` и `{pages}`; другие поля сохраняют отображавшийся текст. |

## Открытие PDF

Пункт «Открыть файл PDF (.pdf)» в меню «Ещё» предлагает выбрать PDF и заменяет документ его содержимым в виде редактируемого текста, который затем можно сохранить в формате Word. Пункт «Открыть файл Word (.docx)» тоже принимает файлы PDF. Как и для файла Word, размер бумаги, ориентация, поля и колонтитулы берутся из файла, текущий водяной знак сохраняется, а замена содержимого — один шаг отмены.

Из кода вызовите `importPdf(file)`. Если файл не удаётся прочитать, документ не меняется и генерируется событие `importError`:

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { DocumentEditor, PdfImportError } from 'nuvra';

const html = ref('');
const editor = ref<InstanceType<typeof DocumentEditor>>();

const open = (event: Event) => {
  const file = (event.target as HTMLInputElement).files?.[0];
  if (file) void editor.value?.importPdf(file);
};

const onImportError = (error: unknown) => {
  // `reason`: 'invalid', 'encrypted' или 'empty'.
  if (error instanceof PdfImportError) console.error(error.reason);
};
</script>

<template>
  <input type="file" accept=".pdf" @change="open" />
  <DocumentEditor ref="editor" v-model="html" @import-error="onImportError" />
</template>
```

PDF хранит не абзацы, а расположенные на странице глифы, поэтому структура документа восстанавливается по раскладке:

- абзацы с выравниванием, отступом первой строки и интервалами; заголовки — по размеру шрифта;
- маркированные и нумерованные списки;
- таблицы из выровненных столбцов: с границами, если PDF их рисует, иначе — как таблицы подписи без границ;
- полужирный, курсив, цвет, размер шрифта и шрифт;
- строки, повторяющиеся вверху и внизу страниц, становятся колонтитулами, номера страниц в них — `{page}` и `{pages}`;
- изображения встраиваются как data URL (не проходят через `uploadImage`);
- размер бумаги и поля.

Читается латинский и кириллический текст встроенных и стандартных шрифтов, включая узбекские буквы.

Файл читается целиком в браузере: ничего не отправляется на сервер, страницы не отрисовываются, а модуль чтения не имеет зависимостей и загружается только при открытии первого PDF. После каждой страницы управление возвращается браузеру, поэтому длинный документ не подвешивает страницу.

`readPdf` возвращает результат без редактора:

```ts
import { readPdf } from 'nuvra';

const { html, page } = await readPdf(await file.arrayBuffer());
```

### Ограничения

| Содержимое PDF | Что происходит |
| --- | --- |
| Отсканированные страницы | Приходят как изображения; для чтения их текста нужно OCR. |
| Зашифрованные файлы | Не открываются; `importError` с причиной `'encrypted'`. |
| Не PDF или файл повреждён без возможности восстановления | `importError` с причиной `'invalid'`. |
| Нет ни текста, ни изображений | `importError` с причиной `'empty'`. |
| Сложная раскладка | Несколько колонок, текст поверх изображений и необычные таблицы восстанавливаются настолько, насколько позволяет раскладка; проверьте результат. |
| Формы, аннотации, ссылки, закладки | Не импортируются. |
| Векторные рисунки и диаграммы | Не импортируются, кроме границ таблиц. |

## Скачивание PDF

> Новое в 0.6.0: «Скачать как PDF», `exportPdf()` и `exportError`.

Пункт «Скачать как PDF» в меню «Ещё» или `exportPdf()` у ref шаблона сразу сохраняет документ в файл PDF, без диалога печати. Имя файла берётся из пропса `title`.

Каждый лист отрисовывается в изображение (через SVG `foreignObject` и canvas, в формате JPEG), и изображения записываются в PDF по одному на страницу. Поэтому PDF выглядит как распечатка — с колонтитулами, водяным знаком, сносками и повёрнутыми страницами, но:

- его текст нельзя выделить, найти поиском или прочитать вслух, а файл больше, чем PDF с настоящим текстом;
- изображения с другого сервера попадают в PDF, только если этот сервер разрешает запрос (CORS); остальные в PDF не включаются;
- веб-шрифт, не установленный на компьютере, может быть заменён в изображении резервным шрифтом.

PDF строится из листов страничного режима. В веб-режиме редактор на время экспорта переключается в страничный режим, а затем возвращается обратно.

Если страницы не удаётся отрисовать — например, потому что браузер не разрешает читать данные canvas, — редактор генерирует событие `exportError`, и файл не скачивается. Путь к PDF с выделяемым текстом по-прежнему — печать с пунктом «Сохранить как PDF» в диалоге печати:

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { DocumentEditor } from 'nuvra';

const html = ref('');
const editor = ref<InstanceType<typeof DocumentEditor>>();

const onExportError = (error: unknown) => {
  console.error(error);
  void editor.value?.print(); // запасной вариант — диалог печати
};
</script>

<template>
  <DocumentEditor ref="editor" v-model="html" title="Договор" @export-error="onExportError" />
  <button type="button" @click="editor?.exportPdf()">PDF</button>
</template>
```

## Сноски

Пункт «Сноска» в меню вставки (кнопка **+**) или в меню `/` вставляет в позицию курсора нумерованную ссылку и открывает небольшую форму для текста сноски. `Ctrl+Enter` или **Сохранить** сохраняет её; **Отмена** или `Escape` закрывает форму, а новая сноска, оставленная пустой, снова удаляется. Щелчок по ссылке открывает форму, в которой можно изменить текст или **Удалить** сноску.

Ссылки нумеруются в порядке следования в документе и перенумеровываются при каждом добавлении, перемещении или удалении сносок. Сноска хранится в самой ссылке вместе с текущим номером:

```html
<p>Акт подписан обеими сторонами<sup data-footnote="Подписанные экземпляры хранятся в архиве.">1</sup>.</p>
```

Где отображаются сноски:

| Место | Сноски |
| --- | --- |
| Страничный режим | Внизу листа, на котором находится ссылка, под короткой чертой; вёрстка оставляет для них место. |
| Веб-режим | Все сноски после документа. |
| Печать и экспорт в HTML из страничного режима | Внизу каждого листа, как на экране. |
| Печать и экспорт в HTML из веб-режима | Все сноски после документа. |
| Экспорт в Word | Собственные сноски Word, нумерацию проставляет Word. |

- Текст сноски — обычный текст без форматирования, до 2000 символов.
- Абзац не разрывается между листами, поэтому его сноски находятся на листе, где он начинается. Блок выше страницы держит все свои сноски на первом листе.
- Из кода: `engine.insertFootnote(text)`, `setFootnoteText(element, text)`, `removeFootnote(element)` и `getFootnotes()`.

## Многоуровневая нумерация

В официальных документах, таких как приказы и положения, пункты нумеруются как 1., 1.1., 1.1.1. Откройте стрелку рядом с кнопкой нумерованного списка и выберите «Многоуровневая нумерация (1.1, 1.2)»; «Простая нумерация (1, 2, 3)» возвращает обычный вид. Если курсор не находится в нумерованном списке, он будет создан.

Вкладывайте пункты клавишей `Tab` и поднимайте их на уровень выше с помощью `Shift+Tab`: каждый вложенный уровень продолжает номер родительского пункта.

```html
<ol data-numbering="legal">
  <li><p>Общие положения</p>
    <ol>
      <li><p>Настоящее положение распространяется на всех сотрудников.</p></li>
      <li><p>Оно вступает в силу с момента подписания.</p></li>
    </ol>
  </li>
  <li><p>Обязанности</p></li>
</ol>
```

Атрибут ставится только на самый внешний список. Экспорт в Word записывает многоуровневую нумерацию, которую Word продолжает сам, а импорт распознаёт такие списки в файлах Word. Из кода: `engine.setListNumbering('legal')` или `'default'`.

## Нумерация страниц

Во всплывающем окне колонтитулов на панели инструментов под полями для текста есть два параметра:

| Параметр | Настройка | Действие |
| --- | --- | --- |
| «Не показывать на первой странице» | `differentFirstPage: true` | На первой странице не выводятся колонтитулы и номер страницы — как нужно для титульных листов и бланков. |
| «Начать нумерацию с» | `firstPageNumber` | Номер, выводимый на первой странице (0–9999); следующие страницы нумеруются дальше от него. |

Оба параметра хранятся в `v-model:page` и не записываются, пока имеют значения по умолчанию. Их учитывают страничный режим, печать, экспорт в HTML и экспорт в Word; в Word они становятся параметром «Особый колонтитул для первой страницы» и начальным номером нумерации страниц. `{pages}` по-прежнему учитывает все листы.

```ts
const page = ref<PageSettings>({
  ...createPageSettings(),
  footer: { left: '', center: '{page}', right: '' },
  differentFirstPage: true,
  firstPageNumber: 0
});
```

При таких настройках на титульном листе нет номера, а следующая страница получает номер 1.

В Word водяной знак является частью колонтитула, поэтому в документе с параметром «Не показывать на первой странице» водяной знак там на первой странице не отображается.

## Страницы разной ориентации

> Новое в 0.6.0: разрывы разделов.

Широкой таблице или диаграмме часто нужна альбомная страница внутри книжного документа. Пункт «Разрыв раздела: альбомные страницы» в меню вставки (кнопка **+**) или в меню `/` поворачивает страницы после курсора; «Разрыв раздела: книжные страницы» возвращает следующие страницы обратно. Из кода: `engine.insertSectionBreak('landscape')` или `'portrait'`.

Разрыв раздела начинает новую страницу, как разрыв страницы. Страницы после него получают ориентацию разрыва до следующего разрыва раздела; размер бумаги и поля остаются теми, что заданы в параметрах страницы. Разрыв, ориентация которого совпадает с ориентацией предыдущих страниц, работает как обычный разрыв страницы.

Он сохраняется как пустой блок:

```html
<p>2. График работ приведён в таблице ниже.</p>
<div data-type="section-break" data-orientation="landscape"></div>
<table>…</table>
<div data-type="section-break" data-orientation="portrait"></div>
<h2>3. Заключительные положения</h2>
```

| Место | Повёрнутые страницы |
| --- | --- |
| Страничный режим | Листы разного размера, выровненные по левому краю. Блоки повёрнутого раздела получают ширину текста своего листа; таблица с явно заданной шириной столбцов сохраняет её, а абзац с правым отступом сохраняет свой правый край. Разрыв отображается двойной линией с подписью ориентации. |
| Веб-режим | Один непрерывный лист с подписанной линией разрыва; печать и экспорт в HTML из веб-режима страницы не поворачивают. |
| Печать и экспорт в HTML из страничного режима | Повёрнутые листы используют именованное правило `@page`, поэтому печатаются на повёрнутой бумаге. Браузер без поддержки именованных страниц печатает их в ориентации документа. |
| PDF | Повёрнутые страницы. |
| Экспорт в Word | Каждый раздел становится разделом Word со своей ориентацией. |
| Импорт из Word | Каждый раздел после первого начинается с разрыва раздела; см. [Ограничения](#ограничения). |

Колонтитулы, водяной знак и номера страниц продолжаются на повёрнутых страницах.

## Оглавление

Пункт «Оглавление» в меню вставки (кнопка **+**) или в меню `/` вставляет оглавление в позицию курсора. В нём перечисляются заголовки уровней 1–3, написанные непосредственно в документе (а не внутри таблиц, списков или цитат), и страница, с которой начинается каждый из них. Для номеров страниц нужен страничный режим; в веб-режиме столбец номеров остаётся пустым.

Оглавление не обновляется при правках само. Если в документе уже есть оглавление, этот же пункт называется «Обновить оглавление» и перестраивает его на месте, где бы ни находился курсор. `updateTableOfContents()` у ref шаблона делает то же самое — например, непосредственно перед сохранением.

Оглавление сохраняется как обычное содержимое — таблица без границ:

```html
<table data-type="toc"><tbody>
```

## Область навигации

Пункт «Область навигации» в меню «Ещё» открывает слева панель с двумя вкладками: **Заголовки** и **Страницы**.

- **Заголовки** — все заголовки документа с отступами по уровню. В страничном режиме у каждого заголовка указана страница, с которой он начинается. Щелчок по заголовку прокручивает документ к нему и ставит курсор в его начало. В документе без заголовков выводится подсказка применить стиль заголовка.
- **Страницы** — маленькое изображение каждой страницы с её номером; повёрнутая страница получает повёрнутое изображение. Щелчок по изображению прокручивает документ к этой странице. Миниатюрам нужен страничный режим; в веб-режиме вкладка сообщает об этом. (Новое в 0.6.0.)

Оба списка обновляются после правок с небольшой задержкой.
